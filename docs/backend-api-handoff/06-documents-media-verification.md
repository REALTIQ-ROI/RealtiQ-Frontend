# Documents, media and verification

Public media and protected documents are distinct data planes. Public media DTOs contain released CDN-safe representations only. Protected documents and evidence use authenticated route families, current profile/resource permissions, version-bound grants, private/no-store headers, current scan state and audit records. Never expose a storage URL, storage key, original filename, hash, signed credential or arbitrary provider URL.

## Upload and metadata routes

| Endpoint | Request/response | Access |
|---|---|---|
| `POST /api/media/upload` | Multipart `files` (array, maximum 10 as mounted); response is uploaded safe media DTO. | Bearer, current profile and `authorizeMediaUpload`; validators run after upload middleware. Upload media only for authorized listing/project resources. |
| `POST /api/documents/properties/:propertyId/title-upload` | Preferred multipart single `file`; optional text fields `documentType`, `title`, `accessPolicy` (JSON when sent), and optional `propertyId` only when it matches the path. One PDF/JPEG/PNG/WebP up to 50 MiB. `201 {document,verification,verificationExisting,riskDetected,nextAction}`. | Bearer + active profile + current `document.issue`/owner-signatory authorization before Multer; then route-bound, file-byte-bound step-up before storage. |
| `POST /api/documents/title-upload` | Deprecated compatibility path; requires `X-Property-ID` matching multipart `propertyId`. Missing header returns `410 DOCUMENT_UPLOAD_ROUTE_DEPRECATED`. | Same bounded parser and byte-bound step-up; header-based current resource authorization runs before parsing. New frontend should use the path-scoped route. |
| `POST /api/documents/projects/:projectId/registered-survey` | Multipart `file` (one file), optional supported title-document metadata fields, private project vault. | Current project authority before parsing; then route/file-bound step-up before storage. |
| `POST /api/documents/title-asset-upload` | Multipart `file` and supported staged-asset metadata; one bounded private title file. | Current seller-profile `document.issue` check before parsing; then route/file-bound step-up. Staged asset is not public or verified. |
| `POST /api/properties/:propertyId/title-documents` | Property-scoped multipart `file`; controller binds `propertyId` from the path after step-up. | Current resource authorization before parsing; then route/file-bound step-up before storage. |

### Multipart step-up for protected title uploads

The routes above and `POST /api/properties/:id/distress-sale-evidence/upload`, `POST /api/properties/:id/listing-verification/evidence`, and `POST /api/title-verifications/:id/verify-document` parse one bounded file before `stepUpMiddleware`. For a file with SHA-256 digest `d`, start the challenge with the exact method, literal mounted path (no query), active profile, and body containing all multipart text fields plus `__stepUpFileSha256: d`. Then submit those same fields and digest, the single `file` part, and `X-Step-Up-Challenge`. The middleware hashes `req.file.buffer`, rejects a missing or changed digest, consumes the one-use challenge only after the comparison, and removes the reserved digest field before controller validation. Challenge IDs are not reusable tokens. Changing file bytes, a text field, profile, method, or path requires a new challenge. The parser limits title documents to one file, 50 MiB, PDF/JPEG/PNG/WebP, eight bounded text fields and nine parts; listing-verification evidence uses its route-specific bounded parser. Do not upload bytes until the preflight response permits parsing.

## Evidence, verification and protected view

Profile evidence: `/api/profiles/current/onboarding/evidence/contract`, GET list/detail/content, POST upload/retry and DELETE. Verification cases: POST `/api/profiles/current/verification-cases`, GET list/detail/history and POST `/:id/state`. Case evidence is identity/profile-bound; use returned allowed-purpose contract. Staff uses `/api/admin/verification-cases` or `/company-verification-cases`; evidence content is private and decisions require independent department authority and step-up.

Listing-verification owner API: `GET /api/properties/:id/listing-verification` returns `{verification-or-requirements}` as the service DTO; `GET .../evidence?before=<id>&limit=25` returns `{evidence:[{id,propertyId,purpose,shotType,capturedAt,mimeType,fileSizeBytes,scanState,createdAt}],nextCursor}`. `POST /api/properties/:id/listing-verification/evidence` is single-file multipart `file` plus text fields `{purpose,operationKey,shotType?,capturedAt?}`. Purposes are `identity|authority|transfer_proof|site_photo|render|commercial_floor_plan|approved_building_plan|parking_capacity`; site photos require `shotType=exterior|living_area|kitchen|bedroom_or_main_room|site_progress` and a capture date; those metadata fields are rejected for other purposes. Upload is private, scan-gated, owner-profile bound, idempotent by `operationKey`, and returns `201 {evidence:{id,propertyId,purpose,shotType,capturedAt,scanState}}`. `POST /api/properties/:id/listing-verification` body is `{expectedPropertyVersion,evidenceDocumentIds:[...]}` and returns `201 {verification:<case DTO>}`. Submission requires current eligible owner, active moderated/unpublished-or-published current listing, clean exact evidence composition, and configured approved `listing_verification` policy; it does not publish the listing. Staff queue/decision is `/api/admin/listing-verifications`; decision is documented in [09](09-admin-console-and-policies.md). Distress evidence has a separate owner route and Admin review under `/api/admin/distress-sale-assessments`. These signals do not merge title-verification status.

Document metadata/access routes include `GET /api/documents`, `GET /api/documents/:id`, `POST /:id/access-requests`, `GET /access-requests`, `POST /:id/grant`, inspection status/retry, `GET /api/title-documents/:documentId/access-status`, `POST /initialize-view-payment`, `POST /open-viewer`, `PATCH /access-policy`, and viewer routes `/api/title-document-viewer/:sessionToken/content|download|end`. The same document router is mounted at singular `/api/document` for compatibility; prefer plural `/api/documents`.

Access is identity + selected-profile + exact document/version/resource based. An access grant or paid receipt is not sufficient after expiry, revocation, document replacement, scan change, ownership/permission change or profile switch. `open-viewer` creates a short-lived server session; content rechecks authorization and scan before and after rendering. Viewer download additionally requires the exact approved download right. Private render is watermarked, `private, no-store`, sandboxed, and uses safe response headers. Quarantined, rejected, stale, unsupported or unconfigured content is not rendered. The actual protected title-renderer formats are PDF/JPEG/PNG/WebP as currently supported; outside-contract content returns an explicit unavailable/unsupported error, not original bytes. Unicode watermark names need an approved TTF/OTF via `PROTECTED_DOCUMENT_WATERMARK_FONT_PATH`; unavailable font returns a 503.

Access policy values: `private`, `paid_view_once`, `paid_view_multiple`, `on_request` for current title-document policy API. Media access level is one of `Free`, `Paid`, `On request`, `Private` where its current media contract supports it. Photos, renders, recorded video and public master/site plan follow source-defined Free treatment; do not expose private survey/title/technical files as public media. Actual fees, scanner and private storage remain policy/provider gated.

## Title verification and registry

- `POST /api/title-verifications` accepts `{propertyId,documentId,documentType,metadata?}`; metadata is limited to `source:"property_creation"|"title_document_upload"`. Current verified seller/profile `document.issue`, exact property/document match and current inspection are required. Duplicate active submission can return existing record/200; new submission returns 201.
- `GET /api/title-verifications`, `GET /:id` are current profile/resource scoped. `PATCH /:id/review`, `POST /:id/retry-anchor`, `PATCH /:id/revoke`, and revocation request routes require current staff role/department, step-up and independent authority as applicable.
- `GET /api/title-verifications/public/:verificationId` is a public proof route; internal ID verify route is private.
- `/api/title-registry` exposes public key, snapshots, manifest, public records/integrity, document verification and external-anchor request. Public registry proof must not be described as statutory title warranty. External anchor requires admin step-up; provider activation is separate.

The public registry DTO is `{record:{publicVerificationId,publicVerificationUrl,registry,property:{publicReference,title,location},documentType,documentHash,hashAlgorithm,legalReviewStatus,registryStatus,verificationVersion,sequenceNumber,previousRecordHash,recordHash,signature,signatureAlgorithm,signingKeyId,signatureStatus,approvedAt,publishedAt,revokedAt?,revocationReason?,supersededBy,externalAnchor:{status,provider,network,transactionId,transactionUrl,anchoredAt},disclaimer}}`. Registry integrity is a direct verifier result; a snapshot returns snapshot sequence/hash/signature/anchor fields; manifest returns `{snapshotDate,snapshotHash,records}` and uses immutable public cache headers. These values establish RealtiQ legal review and document integrity only, not government ownership proof.

`POST /api/title-registry/:publicVerificationId/verify-document` is a public multipart `file` comparison. The route buffers one file using the shared upload middleware; service validates supported title type/size and compares its hash with the registered digest. Response `{matches,publicVerificationId,hashAlgorithm,uploadedDocumentHash,registeredDocumentHash,registryStatus,message?}`; it does not upload/replace the registry document. `POST /api/title-registry/:publicVerificationId/request-external-anchor` requires staff `legal_verification` department, excludes Internal Audit and requires step-up. If adapter config is off, it returns 409 with an unavailable message; success returns `{record}`.

## Staff private-file reconciliation and custody contracts

The router is mounted at both `/api/documents` and `/api/document`; use plural paths for new clients. The singular prefix is a compatibility alias, except the legacy title-upload operation documented above. These are staff/operator workflows, not end-user file-management screens. Mutations require a bearer token, active staff profile, `X-Step-Up-Challenge`, current department/resource permission, and current independent-authority checks. Responses set `Cache-Control: private, no-store` and vary by authorization/profile. Internal Audit is read-only where the service permits it; it cannot prepare, decide, move, attest, or release custody operations.

| Method and path (plural prefix) | Request contract | Success contract | UI and safety behavior |
|---|---|---|---|
| `GET /api/documents/private-migrations/reconciliations/discovery?kind=property&sourceId=<id>` | Query only `kind` and `sourceId`; `kind` is a storage source model supported by the migration service. | `200 {reconciliation:{dryRun,sourceKind,sourceId,inventoryVersion,eligible,replacementContainmentEligible,canonicalSource,codes,members:[{kind,id,classification}]}}`. | Discovery does not move files or authorize a merge. Show conflict `codes`; refresh discovery before prepare. |
| `GET /api/documents/private-migrations/reconciliations/review?after=<id>&limit=25` | `after?` cursor; `limit?` integer 1–100, default 25. | `200 {reconciliation:{entries:[ReconciliationDTO],nextCursor:string|null}}`. | Queue pagination is forward cursor; preserve `nextCursor` exactly. |
| `POST /api/documents/private-migrations/reconciliations` | Step-up. JSON `{kind,sourceId,inventoryVersion,expectedVersion?,mode?}`. `mode` is omitted normally; the only client-selectable value is `replacement_containment`. Do not send internal `relocate` or `adopt_complete` modes; service selects them. | `202 {reconciliation:ReconciliationDTO}`; an idempotent existing operation may be returned. | Expected inventory token is bound to current actor/profile/source inventory. On `409 CONFLICT_RECONCILIATION_INVENTORY`, repeat discovery. |
| `GET /api/documents/private-migrations/reconciliations/:id?before=<auditId>&limit=25` | `before?` ObjectId cursor; `limit?` 1–100, default 25. | `200 {reconciliation:ReconciliationDTO,integrity:{valid,codes},history:[AuditDTO],nextCursor:string|null}`. | `integrity.valid=false` is a hold/review state, not a partial success to ignore. |
| `POST /api/documents/private-migrations/reconciliations/:id/decision` | Step-up. `{expectedVersion,decision:"approve"|"reject",source?,evidenceReference?}`; approval requires a source accepted by the current policy and an opaque evidence reference. | `200 {reconciliation:ReconciliationDTO}`. | Preparer cannot approve; current source inventory and policy revision are rechecked. Never treat approval as public release. |
| `POST /api/documents/private-migrations/reconciliations/:id/recovery` | Step-up. `{expectedVersion,action:"contain"|"reauthorize"}`. | `200 {reconciliation:ReconciliationDTO}`. | A current lease or completed operation conflicts. Recovery does not restore an old public URL. |
| `GET /api/documents/private-migrations/custody/discovery?kind=identity&sourceId=<id>&limit=25` | Query supports `kind=identity|property|project`, `sourceId`, `after?`, `limit?` 1–100 default 25. | `200 {custody:{...}}` page with source version, eligibility/reason and cursor. | Discovery is inventory only; it does not assign ownership or legal title. |
| `POST /api/documents/private-migrations/custody/cases` | Step-up. `{kind,sourceId,sourceKey,sourceVersion,caseReference}`. | `202 {custody:CustodyDTO}`; repeated source key may return existing case. | This records metadata custody only. It does not move bytes, delete a source, or grant access. |
| `POST /api/documents/private-migrations/custody/cases/:id/review` | Step-up. `{expectedVersion,decision:"hold"|"reject"|"recheck",caseReference}`. | `200 {custody:CustodyDTO}`. | `recheck` can bind only an unchanged verified principal. It is not a migration completion action. |
| `GET /api/documents/private-migrations/custody/cases/:id/movement-discovery` | No body; source is selected by case ID. | `200 {custodyMovement:{dryRun,fileId,expectedVersion,eligible,codes}}`. | Any shared-origin or locator conflict remains held. |
| `POST /api/documents/private-migrations/custody/cases/:id/movement` | Step-up. `{expectedVersion}`. | `202 {custodyMovement:CustodyMovementDTO}`. | Creates a proposed movement; worker execution still depends on current approved custody/provider policy. |
| `GET /api/documents/private-migrations/custody/movements/:movementId` | No body/query. | `200 {custodyMovement:CustodyMovementDTO}`. | Poll this resource; do not infer file release from `proposed` or `moving`. |
| `GET /api/documents/private-migrations/custody/movements/:movementId/history?before=<id>&limit=25` | `before?` ObjectId cursor; `limit?` 1–100, default 25. | `200 {custodyMovement:{...CustodyMovementDTO,entries:[AuditDTO],nextCursor:string|null}}`. | Audit DTO omits storage locator, hashes and reviewer identity. |
| `POST /api/documents/private-migrations/custody/movements/:movementId/decision` | Step-up. `{expectedVersion,decision:"approve"|"reject",evidenceReference}`. | `200 {custodyMovement:CustodyMovementDTO}`. | Requires independent compliance decision and unchanged approved policy/source. |
| `POST /api/documents/private-migrations/custody/movements/:movementId/attestation` | Step-up. `{expectedVersion,evidenceReference,evidenceDigest,coverage:["unsigned","signed","versioned","derived"]}`; digest is 64 lowercase hex chars and coverage must contain all four entries. | `200 {custodyMovement:CustodyMovementDTO}`. | Attests complete origin/cache revocation evidence. Distinct approver is still required. |
| `POST /api/documents/private-migrations/custody/movements/:movementId/revocation-approval` | Step-up. `{expectedVersion}`. | `200 {custodyMovement:CustodyMovementDTO}`. | A distinct actor approves revocation evidence; no rollback to public origin is available. |
| `POST /api/documents/private-migrations/custody/movements/:movementId/retry` | Step-up. `{expectedVersion,action?}`; action is `resume|reauthorize|cancel`. | `200 {custodyMovement:CustodyMovementDTO}`. | Active lease conflicts; cancel is disallowed after provider proof/candidate/completion; successful recovery is forward-only. |

`ReconciliationDTO` is `{id,sourceKind,sourceId,state,version,codes,memberCount,mode,processing,attempts,migrationId}`. `CustodyMovementDTO` is `{id,fileId,state,version,attempts,errorCode,completedAt}`. Null `errorCode`/`completedAt` are valid. For state machines, shared errors, and DTOs see [10](10-api-errors-and-state-machines.md), [15](15-api-dto-and-schema-reference.md), and [16](16-api-response-variation-matrix.md). Current available states are not an access grant; client must use the authorized document viewer routes for file bytes.

## Errors and UI states

Show upload progress as local transfer state; server response `quarantined/scanning/activation_pending/held/clean/rejected` is the authority for inspection. Poll the exact status endpoint; retry does not relabel old bytes clean. On `DOCUMENT_SCAN_PENDING`, retain the pending UI and poll; on `DOCUMENT_CONTENT_CHANGED` or `DOCUMENT_ENTITLEMENT_VERSION_CHANGED`, require current version/review; on 403/404 do not reveal whether another profile owns the file. `DOCUMENT_DOWNLOAD_NOT_ALLOWED`, `DOCUMENT_GRANT_EXPIRED`, `DOCUMENT_ACCESS_REVOKED`, `DOCUMENT_VERSION_CHANGED`, `DOCUMENT_UNSUPPORTED_FORMAT`, `FEATURE_DOCUMENT_*`, and `AUTH_STEP_UP_REQUIRED` should be treated as terminal for the attempted action until the user refreshes, obtains a new grant or activation is supplied.
