## Form integration rules

- Use the field dictionary response for client labels, conditions, import eligibility, visibility and validation hints, but treat server validation as authoritative.
- Send only changed editable canonical paths. For an explicit reset-to-inherited action use the entity workflow’s reset/override operation; do not send a guessed sentinel.
- Keep null, false, numeric zero, empty arrays, POA flags, “None” and missing fields distinct. For money, POA is explicit and does not mean zero.
- Keep `reservePrice`, title evidence, KYC, seller authority, transaction-generated sale fields, media bytes, publication actions and identity-derived fields out of generic listing payloads.
- Draft success does not imply publication readiness. Use readiness responses and resolve only field-specific blockers.
- Public/owner/admin views are separate DTOs; never build a public DTO by spreading a private model.
