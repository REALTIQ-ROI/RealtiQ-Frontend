# API response-variation matrix

This is a source-traced state index. It covers the major first-batch workflow families and the four previously open contract families. It does not claim that a single generic response shape applies to all 594 mounted registrations. The complete mounted path/classification index is [14](14-mounted-endpoint-index.md); endpoint-specific success DTOs remain in their feature guides and [15](15-api-dto-and-schema-reference.md).

## Route-level coverage boundary

This matrix currently has **45 response-variation rows**. Rows may combine multiple endpoint methods or an endpoint family, so the count must not be reported as 45 or 594 fully documented endpoint variations. The mounted inventory in [14](14-mounted-endpoint-index.md) contains 594 registrations, including 411 classified first-batch user/staff registrations. A static exact-path check found method/path mentions outside the inventory for 128 of 332 end-user and 61 of 79 staff registrations (189 total). Those references do not prove a complete request/response/error contract. The feature guides contain five fenced HTTP request snippets, one fenced HTTP response snippet and representative successful bodies for five distinct route operations; they are examples for a subset only. The 45 matrix rows mention 44 unique mounted path patterns, but do not enumerate every variation for those routes. The handoff has no systematic per-route variation/error table for all 411 registrations.

For routes without an endpoint-specific entry in this matrix or a full feature-guide contract, use the route index to locate source, but treat the frontend contract as **not yet documented**. Do not infer a response variation from a neighboring endpoint or a shared route family.
## Cross-cutting response handling

- Errors may be `{message,code}` or validation `{code,errors:[...]}`; see [10](10-api-errors-and-state-machines.md).
- `202` indicates accepted asynchronous/provider work only where the named endpoint is implemented to return it. Poll that resource’s status endpoint rather than a guessed generic job endpoint.
- Empty arrays and zero-total pagination are successful empty states, not errors.
- This matrix does not turn uncertain routes in [14](14-mounted-endpoint-index.md) into supported UI contracts. Rows marked unresolved in [13](13-backend-acceptance-and-contract-review.md) remain unresolved until their controllers are traced.
